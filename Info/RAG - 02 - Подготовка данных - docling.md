
## 📦 Модуль 1: Подготовка данных

### 1.1 Загрузка документов разных форматов

#### Почему формат документа — это проблема

PDF, DOCX, PPTX, HTML — у каждого формата свои особенности хранения текста. PDF хранит текст как набор позиционированных элементов на странице, а не как связный поток. Это означает три класса проблем:

**Проблема порядка чтения** в многоколоночных документах. Наивный парсер читает слева направо, строку за строкой — в результате текст правой колонки перемешивается с текстом левой. Embedding такого мусора даёт бесполезный вектор.

**Проблема таблиц.** Таблица в PDF — это сетка позиционированных текстовых элементов. PyPDF2, стандартный инструмент эпохи 2020–2023, извлекает их построчно, уничтожая структуру:

```
РЕАЛЬНАЯ ТАБЛИЦА В PDF:          PyPDF2 извлечёт:
┌───────────┬──────────┐
│ Показатель│ Значение │ →  "Показатель Значение Выручка 1.2B EBITDA 340M"
│ Выручка   │ 1.2B     │     (мусор для embeddings и для LLM)
│ EBITDA    │ 340M     │
└───────────┴──────────┘
```

**Проблема OCR и scan.** Сканированный PDF — это изображение. Без OCR парсер возвращает пустую строку. Даже с OCR — артефакты: `"\x0c"`, `"\ufeff"`, битый юникод, перепутанные буквы.

#### Современные парсеры: сравнение

```
ПАРСЕР          ДЕПЛОЙ          ТАБЛИЦЫ   КОЛОНКИ     ЛИЦЕНЗИЯ
─────────────   ──────────      ────────  ────────    ────────
Docling (IBM)   self-hosted ✅   хорошо    хорошо      MIT
Marker-PDF      self-hosted ✅   отлично   отлично     GPL-3.0
LlamaParse      cloud API        отлично   средне      проп.
PyMuPDF4LLM     self-hosted ✅   средне    средне      AGPL
PyPDF2          self-hosted ✅   плохо     плохо       MIT
```

**Docling** — выбор по умолчанию для закрытого контура. MIT-лицензия, IBM Research, теперь под LF AI & Data Foundation. Использует ML-модели:

- `page_layout_analysis` — детектирует текстовые блоки, заголовки, таблицы, формулы и их пространственные связи
- `TableFormer` — модель глубокого обучения IBM для детекции структуры таблиц (строки, колонки, заголовки) без регулярных выражений
- `reading_order` — восстанавливает корректный порядок чтения с учётом колонок и сносок

Docling поддерживает единый API для PDF, DOCX, PPTX, XLSX, HTML, изображений и LaTeX. Результат — унифицированный `DoclingDocument`, экспортируемый в Markdown, HTML, JSON или DocTags. Первый запуск скачивает ML-модели (~1-2 GB), все последующие — оффлайн. Документ не покидает машину — критично для 152-ФЗ, ISO 27001.

#### ✏️ Код: Docling в действии

Установка:
```bash
pip install docling
```

Базовое использование:
```python
from docling.document_converter import DocumentConverter

converter = DocumentConverter()
result = converter.convert("report_2025.pdf")
markdown_text = result.document.export_to_markdown()
# Таблицы сохранены как Markdown-таблицы ✅
# Заголовки → ##, списки → -, порядок чтения восстановлен
```

Пакетная обработка директории:
```python
import os

parsed_docs = {}
for pdf in os.listdir('/workspace/docs/'):
    if not pdf.endswith('.pdf'):
        continue
    result = converter.convert(f"/workspace/docs/{pdf}")
    parsed_docs[pdf] = result.document.export_to_markdown()
    # Сохраняем .md для проверки и отладки
    with open(f"/workspace/docs/{pdf.replace('.pdf', '.md')}", 'w') as f:
        f.write(parsed_docs[pdf])
```

Ключевой момент: откройте полученный `.md` в редакторе. Если таблицы выглядят как `| col1 | col2 |` — парсер работает правильно. Если это каша из слов — переходите на Marker-PDF или LlamaParse.

#### Форматы помимо PDF

В enterprise редко работают с одним PDF. Реальный корпус содержит:

```
ТИП ДОКУМЕНТА    ПАРСЕР/ЗАГРУЗЧИК             ОСОБЕННОСТИ
──────────────   ─────────────────────────    ──────────────────────────
PDF              Docling, Marker-PDF           таблицы, OCR, layout
DOCX/PPTX        Docling (единый API)          трекинг изменений → отключить
HTML/Web         BeautifulSoup + trafilatura   навигация и реклама → чистить
Markdown/RST     прямая загрузка              структура заголовков → metadata
JSON/CSV         pandas + jinja template       структурировать перед chunking
Email (EML)      mailparser + html-clean       убрать цитаты, подписи
Code (py/js)     AST-парсер (tree-sitter)      чанковать по функциям/классам
```

Ключевая мысль: формат документа определяет стратегию парсинга. Единый инструмент для всех форматов — Docling. Но его следует дополнять специализированными инструментами для edge-кейсов.
