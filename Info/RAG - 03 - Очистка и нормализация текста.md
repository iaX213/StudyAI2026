
### 1.3 Очистка и нормализация текста перед индексацией

Embeddings чувствительны к шуму: дубликаты пустых строк, колонтитулы, OCR-артефакты смещают вектор и ухудшают поиск.

#### Что обязательно убрать

```
КАТЕГОРИЯ               ПРИМЕР                           ДЕЙСТВИЕ
─────────────────────   ──────────────────────────────   ─────────────────
Колонтитулы             "Стр. 14 из 87 | ООО Ромашка"    re.sub удалить
Номера страниц          "- 23 -", "page 23 of 87"        re.sub удалить
OCR-мусор               "\x0c", "\ufeff", "\u00ad"       replace/strip
Битые переносы          "авто-\nматически"               re.sub + join
Лишние пробелы          "слово    следующее"             нормализовать
Дублированные строки    """...\n\n\n..."""               re.sub \n{3,}→\n\n
HTML-теги               "<p>текст</p>"                   BeautifulSoup
Boilerplate             "КОНФИДЕНЦИАЛЬНО. ©2025"         список регулярок
```

#### ✏️ Код: функция очистки текста

```python
import re

def clean_text(text: str) -> str:
    # Убираем колонтитулы с номерами страниц
    text = re.sub(r'Стр\.\s*\d+\s*(из\s*\d+)?', '', text)
    # Нормализуем множественные переносы строк
    text = re.sub(r'\n{3,}', '\n\n', text)
    # Убираем OCR-мусор
    text = text.replace('\x0c', '').replace('\ufeff', '')
    # Нормализуем пробелы (множественные → один)
    text = re.sub(r'[ \t]+', ' ', text)
    return text.strip()
```

Применение в pipeline — перед чанкингом:

```python
# В pipeline: парсинг → очистка → чанкинг
raw_markdown = result.document.export_to_markdown()
clean_markdown = clean_text(raw_markdown)
chunks = contextual_chunk(doc_name, clean_markdown, llm)
```

#### Нормализация — не только про мусор

Для технических корпусов важно:

- **Аббревиатуры:** "ИБ" и "информационная безопасность" — разные токены. Решение: словарь синонимов → expand перед embedding
- **Даты:** "01.01.2025", "1 января 2025", "2025-01-01" — три токенизации одного факта
- **Единицы измерения:** "100 МБ", "100MB", "102400 КБ" — нормализовать к каноническому виду

#### Metadata — это не декорация

Каждый чанк при вставке в vectorstore должен нести структурированные метаданные. Они нужны для фильтрации при поиске и для Citations пользователю:

```
METADATA НАБОР (минимальный):
  source:      имя исходного файла
  doc_type:    тип документа (regulatory, manual, ticket, code)
  created_at:  unix timestamp (для временной фильтрации)
  chunk_id:    порядковый номер в документе
  section:     заголовок раздела (Docling умеет извлекать)
  page_num:    номер страницы (для Citation → пользователь видит источник)
```

Без metadata нет Citations. Без Citations — RAG непригоден для enterprise.
